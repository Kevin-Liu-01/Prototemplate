# Vercel

Use this as the single executable router for Vercel work.

## Routing

- Platform operations route to CLI, API, deployments, env vars, functions, routing, firewall, storage, queues, cron, and observability references.
- AI and agent work routes to AI SDK, AI Gateway, chat SDK, sandbox, agent, browser verification, and persistence references.
- Frontend workflow routes to React best practices, shadcn, Satori, v0, Turborepo, and Turbopack references.
- Vercel Labs `agent-skills` imports route through existing owners: `web-design-guidelines`, `vercel-react-best-practices`, `react-view-transitions`, `component-composition-style`, and the folded `vercel-cli-with-tokens` reference. Do not add a duplicate executable just because an upstream Vercel skill exists.

## Agent-Skill Working Agreement

- Use `VERCEL_TOKEN` from the environment; do not pass tokens with `--token`.
- Default deployments to preview. Use production only when the user explicitly asks.
- Read `.vercel/project.json` or `.vercel/repo.json` for state, but do not edit `.vercel/` files directly.
- Prefer `--format json` for deploy lists and project/deployment inspection when the next step needs structured data.
- For optimize/performance audits, require metric-backed evidence from the project; do not silently turn a Vercel optimize run into generic code review.
