# MODULES PLAN — five minimalist directions, organised by module

This document is the build contract. It is written to be read in the order the founder presents:
**module by module**, so that a single module can be pulled up across all five directions and
rated on its own. Five builders should be able to work in parallel from this document and invent
nothing. Where a number, a string, a locale code or a filename appears here, it is real and it is
to be used verbatim. Where something is genuinely still open, it is named as open in Part 5.

Read Part 2 (the frame) before building anything. The frame is not a suggestion; it is the reason
five directions will look like one company. Part 1 tells you what goes in each band and what the
band has to prove. Part 3 tells you which of the five you are building. Part 4 is the first
product page and it is the same frame in dark mode.

## The five directions, in one line each

| # | Codename | Slug | Signature demonstration technique | Accent |
|---|----------|------|-----------------------------------|--------|
| 1 | **HALFTONE** | `halftone` | Every non-type visual is a 1-bit Bayer-dithered field rendered by `dither.ts`. No greys exist except dithered ones. | none — the page is achromatic |
| 2 | **CALIPER** | `caliper` | The annotated artefact: hairline metric guides, bezier control points, sidebearing bands and tiny mono labels laid over real letterforms and real UI. | pale sage `#DCE6DA` band + `#4F6B4B` hairline |
| 3 | **REFLOW** | `reflow` | The live re-measure: real DOM changes language and the layout visibly re-measures around it (FLIP). | GT blue `#458DFF` light / `#6BA5FF` dark |
| 4 | **LEDGER** | `ledger` | The aligned column: every diagram is a table in which one column is the invariant. | no hue; second surface `#F4F3EC` beige |
| 5 | **REDLINE** | `redline` | The real artefact, diffed: terminal transcripts, unified diffs, PR pages, generated JSON — line for line. | two diff hues, gutters only |

Every direction is minimalist under the same definition: restrained type (Switzer capped at
weight 500), hairline structure, generous whitespace, no ornament, no decorative gradients, and
**no eyebrows above headings**. A section begins with its heading.

# PART 1 — THE MODULE SYSTEM

Eighteen modules. Fourteen of them appear on the main page in the order given; four (M04's
extended form, M08, M10, M12) also recur on product pages. Each entry carries what the module
must accomplish, the copy in full, the diagram in enough prose to build from, and the direction
that owns the strongest version.

Two laws govern every diagram in this Part and they are worth stating before the list:

**The still-frame law.** The review harness captures stills. Every diagram below nominates a
**canonical still** — one frozen frame that carries the whole argument with no motion and no
caption. If the canonical still does not make the point, the diagram is wrong, and no amount of
animation fixes it. Motion is a second layer that rewards the reader who waits; it is never the
first layer.

**The artefact law.** Nothing is illustrated that can be shown. Every code block, every locale
code, every filename, every terminal line, every JSON key in this document exists in the product.
Where a translated string is needed, it comes out of
`/Users/kevinliu/gt/gt/examples/next-ssg/public/_gt/{es,ja,de,fr,zh}.json` or is generated by
running the product — it is never hand-written by a builder.

## M02 — Hero

**What it must accomplish.** Say what the product is in six words, prove it is for developers in
one line of shell, and put one working demonstration on screen above the fold.

**Copy.**

- Command chip, above the h1: `$ npx gt@latest` — Geist Mono 16, `$` in muted `#867E8E`, the
  command in ink, a copy glyph at the right, click copies `npx gt@latest`. This is not an eyebrow.
  It is a functional artefact and it is deliberately the topmost element of the page; the founder's
  own code comment says it is there "to emphasize that we are a developer first company." Keep it.
- **h1:** `Launch in every language`
- **Subhead:** `Wrap your JSX in <T>, run one command, and ship every string in 100+ languages.`
- **Fine print, third line, Inter 16 muted:** `Open source SDKs for Next.js, React, React Native,
  TanStack Start, Node and Python.` — the word "Open source" is an underlined link to
  `github.com/generaltranslation/gt` (`underline decoration-[#E5E4E7] underline-offset-4`).
- **Buttons:** **Get started** (primary → `/dashboard`) · **Read the docs** (outline → `/docs`).

The hero copy block is shell S2: no top border, `pt-14 pb-6`, inner column capped at 672px,
centred, `gap-10` between the text stack and the button row. The hero **visual** is the band
directly beneath it, `border-top: 1px`, 640px tall, ticked.

**Diagram — "the still half and the moving half."** The hero visual is a two-part composition that
is the same in all five directions in structure and different in every direction in execution. On
the left, a code panel that never changes. On the right, a rendered frame that does.

The left panel is a dark surface (`#14121A`) inset from the left rule by 40px, 599px wide, with a
hairline ring drawn as `outline: 1px rgba(255,255,255,.20); outline-offset: 2px` and
`border-radius: 4px 0 0 4px` — squared on the right because it continues under the right half.
It holds this, verbatim, Geist Mono 14/24, with line numbers in `#867E8E`:

```tsx
import { T, Num, DateTime } from 'gt-next';

export default function Home() {
  return (
    <T>
      <main>
        <h1>Hello, world!</h1>
        <p><DateTime>{new Date()}</DateTime></p>
        <p>
          General Translation builds full-stack
          infrastructure for localizing apps, docs,
          and websites.
        </p>
      </main>
    </T>
  );
}
```

The right half is a browser frame — traffic lights, a URL pill reading `example.com`, and beneath
it a strip of six language tabs with native names: `English (US)` · `Español` · `Français` ·
`日本語` · `Deutsch` · `中文`. The page inside renders the same component in the active locale,
using the real strings: `"Hello, world!"` becomes `"¡Hola, mundo!"`, `"こんにちは、世界！"`, and
the body sentence becomes the real translated sentence from the `_gt` files. The date under the
title is formatted by `Intl.DateTimeFormat` in the active locale, so it changes shape too —
`Jul 29, 2026` → `29 jul 2026` → `2026/07/29` → `29.07.2026`.

**What moves.** Only the right half. Every 3.2 seconds the active tab advances and the rendered
page crossfades its text in 220ms while its **containers re-measure** — the `<h1>` block widens
for German, the paragraph gains a line, the date pill narrows for Japanese. The left panel is
frozen. That contrast is the entire argument and it must be visually obvious that the left half is
not participating.

**What the viewer understands after two seconds.** "The code on the left produced every version on
the right, and I did not have to change it."

**Canonical still.** Active tab `日本語`, the browser frame showing the Japanese page, the code
panel showing the identical English source, and a hairline leader drawn from the `<h1>Hello,
world!</h1>` line in the code to the `こんにちは、世界！` heading in the frame. One line, 1px,
rule-coloured, no arrowhead. The still reads without any motion at all.

**Strongest in: REFLOW.** REFLOW is the direction whose hero *is* the re-measure, so it earns the
right to make the resizing the point rather than a side effect: in REFLOW the browser frame is
live DOM with `getBoundingClientRect` diffing and FLIP transitions at 420ms `power3.out`, and a
thin blue measurement bracket (`#458DFF`, 1px, with 4px end caps) draws itself under whichever
element just changed width, labelled with the delta in Geist Mono 12 — `+18%`, `−31%`. Nothing
else on the page uses blue. See Part 3 for the exact hero variant.

## M03 — Trust

**What it must accomplish.** Convert six logos into one claim, in under 200px, without a kicker.

**Copy.** The band has a heading, because every band has a heading and never a label above one.
The heading is the claim: **`Cursor, Ramp and Profound ship in over thirty languages`** — Switzer
500 at 24/28, left-aligned in a `p-10` cell that occupies the left third of the band. The right
two thirds is a four-across ruled strip, 72px tall, of the six verified wordmarks: **Cursor**
(cursor.com) · **Ramp** (ramp.com) · **Mintlify** (mintlify.com) · **Profound**
(tryprofound.com) · **Partiful** (partiful.com) · **ClickHouse** (clickhouse.com). Assets are the
existing `public/logos/{name}.{light|dark}.svg` pairs, each `max-w-20 max-h-10 object-contain`,
each a link opening in a new tab. Never add a seventh name.

**Diagram.** Not a marquee. A static ruled strip, hairline between each mark, marks at
`opacity: .35` and `filter: grayscale(1)`, rising to full on hover with no scale and no shadow.
The restraint *is* the diagram: confident companies do not animate their logo wall.

**Canonical still.** The whole band. It is static by design.

**Strongest in: HALFTONE.** In HALFTONE each wordmark is rasterised once through
`makeGlyphField` and rendered 1-bit at `scale: 2`, so a logo is a field of hard black cells on
white with no anti-aliasing and no grey. It solves the logo-wall problem that every minimalist
site has — how to make six mismatched brand marks belong to one page — by putting all six through
the same 1-bit process. They become artefacts of this page rather than borrowed assets. Cache the
dithered result; do not re-render per frame.

## M04 — Code

**What it must accomplish.** Show the four component APIs doing four things that a reader believes
are hard, in one band, with no prose about "developer experience."

**Copy.** This is a 2×2 quadrant (shell S6), 719px columns, every cell `p-10`.

Cell (a) — **`Wrap the JSX, not the strings`** / "There is no extraction step and no key file.
`<T>` ships what you already wrote." Checkmarks: "Nested `<b>`, `<a>` and `<i>` survive
translation" · "Translated at build time, served pre-generated" · "`$context`, `$id`, `$maxChars`
and `$requiresReview` steer one entry from the call site".

Cell (b) — **`The name stays, the sentence moves`** / "Mark user data as a variable and it passes
through untouched, in the right place in the sentence."

Cell (c) — **`Numbers, money and dates, locally`** / "Formatted with `Intl` on the client. The
value never leaves the device."

Cell (d) — **`Strings that aren't JSX`** / "Labels, placeholders and `aria-label` translate with
one call, in the language of the request."

**Diagram (a) — the invalid case, shown on purpose.** The cell's payload is a small code panel
holding two snippets stacked with a hairline between them. Above the rule, the working form:

```tsx
<T>Today, I went to the <b>store</b> to buy some <i>groceries</i>.</T>
```

Below the rule, the failing form, with a red squiggle under `{greeting}` and a quick-fix callout
in Geist Mono 12 reading `static-jsx — wrap dynamic children in <Var>`:

```tsx
<T>{greeting}</T>
```

The rule name is real: it is from `packages/react-core-linter/src/rules/`. Showing the failure is
the credibility move; every reader has been burned by a wrapper that silently did nothing.

**Diagram (b) — the sliding slot.** One sentence, drawn four times, one per row, in Inter 18/28.
Translated words are muted `#867E8E`. The variable is one accent-boxed token containing `Alice` —
a 1px box, radius 4, 2px 6px padding — and it is **the same box, the same width, in all four
rows**. What changes is its horizontal position:

```
en   Hello, [Alice]!
es   ¡Hola, [Alice]!
ja   [Alice] さん、こんにちは！
de   Hallo, [Alice]!
```

Under the four rows, a single vertical hairline drops through the four box positions, so the
reader sees a zig-zag: the slot moved, the value did not.

**What the viewer understands after two seconds.** "Word order differs per language, so I cannot
concatenate strings — the variable has to be a slot inside a translated sentence."

**Canonical still.** All four rows visible at once with the connecting hairline. This diagram is
better as a still than in motion; if it animates at all, it is only the accent box travelling
between the four positions on a 4-second loop, and the still is the `ja` row.

**Diagram (c) — the separator flip.** A three-row, four-column table. The column heads are locale
codes in Geist Mono 12 uppercase: `EN-US` · `DE-DE` · `JA-JP` · `AR-EG`. The row labels are the
components themselves as code chips: `<Num>`, `<Currency currency="EUR">`, `<DateTime>`. The cells
hold **live `Intl` output** rendered at build time from the same three source values —
`1_000_000_000`, `1234.50`, `new Date()`. Do not hand-write the cells. The two-second tell is the
thousands separator flipping between `,` and `.` down the `DE-DE` column, and the euro symbol
moving from prefix to suffix in the same column. A 12px mono footnote under the table reads
`Formatted locally with Intl. No network request.`

**Diagram (d) — the form.** A small rendered form, not a code panel: a label, a text input with a
placeholder, and a submit button. All three strings go through `gt()`. On locale change the
placeholder text inside the input changes, the button grows wider, and the label above reflows to
two lines. Placeholders are the right proof here because readers know a JSX wrapper cannot reach
inside an attribute. Real strings: label `Email address` → `Correo electrónico`; placeholder
`you@company.com` (unchanged, and that is worth noticing); button `Get started` → `Empezar`.

**Strongest in: REDLINE.** REDLINE renders cell (a) as a **unified diff** rather than two
snippets: the same file before and after `npx locadex@latest start` touched it, with `-` lines
showing bare JSX and `+` lines showing the same JSX wrapped in `<T>`, `@@ -1,6 +1,9 @@` hunk
header and all. It is the only direction where the reader sees that adopting `<T>` is a *patch*,
not a rewrite — five red lines, five green lines, same structure. That reframing is worth more
than any amount of syntax highlighting.

## M05 — Story

**What it must accomplish.** Put the six stages of the pipeline in order once, so that every later
module can be understood as a part of a whole rather than as another feature.

**Copy.**

- **h2:** `Ship it the way you wrote it`
- **Subhead:** `Source in your repo, translations in your repo, review in the dashboard, delivery
  at the edge.`

Six beats. Each is a heading of one word and a sentence of ≤ 90 characters.

1. **Write** — `JSX goes in <T>, strings go through gt(). Nothing is extracted.`
2. **Scan** — `npx gt translate reads your source and finds only what changed.`
3. **Translate** — `New content is sent. Local edits are preserved. --force is opt-in.`
4. **Review** — `Approve per entry and per locale in the editor, or let it ship.`
5. **Ship** — `Translations land in public/_gt/[locale].json and you commit them.`
6. **Update** — `Fix a string in the dashboard and the CDN serves it without a deploy.`

**Diagram — the six-station rail.** A horizontal rail across the full 1440 column at a fixed
y-position, drawn as a 1px rule with six 10×10 tick triangles on it (the same triangle primitive
as the page's chapter joints, rotated to point down). Above each tick, the one-word heading; below
each tick, the sentence, capped at 200px so all six columns are equal. Between stations 5 and 6
the rail changes from solid to dashed, because station 6 is the only one that happens after your
build has shipped — and that single change of line style says "this one is different" with no
label.

Under each station sits a **20px-tall artefact strip**, not an icon: for Write, four lines of code
silhouette with one wrapped in a bracket; for Scan, a scanline crossing eight code lines; for
Translate, five locale chips filling from empty to solid left to right; for Review, a grid of six
cells with one green and one amber; for Ship, a file path in Geist Mono 12 reading
`public/_gt/ja.json`; for Update, a browser frame with a `no deploy` chip.

**What moves.** A single filled dot travels the rail left to right on a 7.2-second loop, 1.2s per
station, pausing at each tick, and the station it occupies raises its artefact strip from muted to
ink. This is the existing `LocadexFlowchart.tsx` timing (~1.2s/step) reused, so it will already
feel like the product.

**What the viewer understands after two seconds.** "There are six stages, they are in order, and
the last one does not need a deploy."

**Canonical still.** The dot at station 3 (Translate), locale chips half filled, all six headings
and all six sentences legible. Every mid-loop frame must be unambiguous; a frame where the dot is
between stations is a failure.

**Strongest in: REFLOW.** REFLOW replaces the six static artefact strips with one continuous
element: a single small mock website that sits above the rail and is **re-laid-out at each
station** — at Write it is English with visible `<T>` brackets; at Scan a labelled cursor chip
reading `locadex` hops onto a text node; at Translate the node's text changes language and the
card it lives in visibly grows taller with a FLIP transition; at Review a review pill appears; at
Ship the brackets disappear; at Update the text changes once more with no page reload. It is the
D1 mechanic used as narration rather than as decoration, and REFLOW is the only direction with the
machinery to make six consecutive re-measures read as one story.

and a seventh column headed `gt.config.json` is filled in every row and tinted `#F4F3EC`. The
invariant is literally a column. The tab bar still exists above it and still swaps the code panel,
but the argument no longer depends on the tab interaction at all — it is visible in one still, at
one glance, which is exactly what a module-by-module review rewards.

## M07 — Measure

**What it must accomplish.** Move translation from a text problem to a layout problem in one
frame, and name the mechanism that solves it.

**Copy.**

- **h2:** `Your layout has to survive translation`
- **Subhead:** `Get started is 11 characters in English, 13 in German and 3 in Japanese. Every one
  of them has to fit inside the same button.`
- **Metric labels,** Geist Mono 11 uppercase, `+0.3px` tracking, muted: `ASCENDER` · `CAP HEIGHT`
  · `X-HEIGHT` · `BASELINE` · `DESCENDER` · `SIDEBEARING` · `ADVANCE`
- **Specimens:** `Hello` · `Hola` · `こんにちは` · `مرحبا` · `Übersetzen`
- **Real UI strings, with their measured deltas:** `Get started` → `Empezar` · `Jetzt starten` ·
  `始める` · `Commencer`; `Email address` → `Correo electrónico`; `Payment received` →
  `Paiement reçu`
- **Enforcement chip:** `$maxChars={20}`
- **Footnote,** Geist Mono 12 muted: `Widths measured at render with measureText, not typed.`

**Diagram — the instrument.** A full-bleed live SVG, 640px tall, on the page's own paper ground —
this is the one module where a full-bleed band contains no dark surface at all.

Centre of the frame: one word set in Switzer 500 at 160px, filled in `#D8D6DC` rather than ink, so
that the guides drawn over it stay readable. Its outline carries **visible bezier control points**
— 4px filled squares in ink at each on-curve point, 3px hollow circles at each off-curve handle,
joined to their anchors by 1px hairlines. Five horizontal hairline guides run the full width of
the band, each labelled at the left margin in the mono metric labels above; the baseline guide is
the only one at full opacity, the rest at 40%. Two pale sage vertical bands mark the left and right
sidebearings, and a horizontal bracket beneath the word marks the **advance width**, labelled with
the measured pixel value in Geist Mono 12. Ruler ticks — 4px marks every 8px, 8px marks every 40px
— run along the top and bottom margins of the band.

**What moves.** The specimen cycles `Hello → Hola → こんにちは → مرحبا → Übersetzen` on a 3-second
dwell, and the instrument re-measures itself around each one:

- `Hola`: the advance bracket contracts; the guides do not move.
- `こんにちは`: the descender guide **fades out entirely** (there are none), the x-height guide
  rises to meet the cap-height guide, and a new label appears reading `NO DESCENDERS`.
- `مرحبا`: the sidebearing bands swap sides, the advance bracket's arrow reverses, and a label
  reads `RTL · CONNECTED BASELINE`.
- `Übersetzen`: the advance bracket **extends past the width the previous words occupied**, a
  second bracket appears above it showing the English `Translate` for comparison, and the delta is
  labelled `+43%`. The diaeresis pushes above the cap-height guide and a small callout marks it.

All guide transitions are 520ms `cubic-bezier(0.16, 1, 0.3, 1)`; labels cross-fade in 200ms. The
control points re-solve per glyph, so they must be generated from the font's real outlines, not
placed by hand — sample the path with `getTotalLength` if you cannot read the glyf table.

**What the viewer understands after two seconds.** "These people measure type across writing
systems, and my button is going to break."

**Canonical still.** `Übersetzen` with both advance brackets visible and the `+43%` delta label.
Second-choice still: `こんにちは` with the descender guide greyed out and `NO DESCENDERS` showing.
Both must be legible with no motion.

**Below the instrument,** a 320px band of the same module carries the consequence: three real UI
elements drawn twice each, English above and German below, at the same font size in the same
container — a button (`Get started` / `Jetzt starten`), a nav row of five items, and a small badge
(`Payment received` / `Paiement reçu`). The German button is visibly wider, the German nav row has
wrapped to two lines, and the German badge has broken to two lines and pushed its row taller. To
the right of each pair, a `$maxChars` chip shows the cap that would have prevented it.

**Strongest in: CALIPER.** This module is CALIPER's thesis statement and CALIPER should carry the
instrument at full 1440 width as its second band, immediately under the hero, before anything else
on the page. In the other four directions the module is 640px tall and sits mid-page; in CALIPER
it is the page's second impression. CALIPER also extends the technique everywhere else: its code
panels get sidebearing bands on the gutter, its buttons get advance brackets on hover, and its
pricing rows get measured leaders. See Part 3.

## M08 — Locadex

**What it must accomplish.** Make an autonomous agent editing your codebase feel safe and obvious
at the same time, by showing that its output is a pull request.

**Copy.**

- **h2:** `Connect a repo. Get a pull request.`
- **Subhead:** `Locadex reads your codebase, writes the internationalization, generates the
  translations, and opens a PR you review.`
- **Checkmarks:** "Every change arrives as a reviewable PR on `locadex/`" · "Auto-merge is off by
  default" · "Setup is its own PR, and you merge it first" · "Next.js, Mintlify, Fern, Docusaurus,
  Vite, React Router and TanStack Start"
- **Buttons:** **Connect GitHub** →
  `/dashboard/api/integrations/github/start?returnTo=%2Fproject%2Flocadex` · **Read the docs** →
  `/docs/platform/locadex`
- **Five step labels, verbatim from the current site:** `Push to repo` / "A commit or PR triggers
  the workflow" · `Scan codebase` / "Agent maps out what has changed" · `Edit code` / "Agent
  internationalizes code and strings" · `Translate content` / "Agent creates translations in
  context" · `Open PR` / "Pull request created for review"
- **Three template names, verbatim:** `Generate code` · `Generate translations and push` ·
  `Keep locales in sync`
- **Three trigger names, verbatim:** `A pull request changes` · `A commit is pushed` ·
  `Started manually`

**Diagram — the PR, at full width.** This module owns the page's dark pivot band, and inside it
the diagram is the largest single object on the site: a GitHub pull-request frame spanning the

# PART 2 — THE FRAME

The frame is one system in two modes. The measured teardown established that viteplus.dev and
oxc.rs are literally the same stylesheet with the base flipped — viteplus's heading colour
`#16171D` is oxc's page background — which is why "main page like viteplus, product pages like
oxlint" is one brief and not two. Build one frame, run the marketing page light and the product
pages dark, and switch it with one attribute.

Everything in Part 2 marked **fixed** is identical across all five directions. If two directions
disagree on a fixed value, they are both wrong. Everything marked **free** is where a direction
gets to be itself.

## 2.1 The column — fixed

One class carries the entire layout system. Call it `.band`. There are roughly two dozen instances
on a page and nothing else does layout.

```css
.band {
  margin-inline: auto;
  position: relative;
  overflow-x: clip;
  border-color: var(--rule);
}
@media (min-width: 48rem) {            /* 768px */
  .band { border-left: 1px solid; border-right: 1px solid;
          max-width: calc(100vw - 2rem); }   /* 16px gutter each side */
}
@media (min-width: 90rem) {            /* 1440px */
  .band { max-width: 90rem; }          /* hard cap 1440px */
}
[data-theme='dark'] .band { border-color: var(--rule-dark); }
```

Max content width **1440px**. Gutters **16px** each side from 768px to 1440px; above 1440 the
column centres and the gutter grows. **Below 768px the side rules switch off entirely** and content
runs edge to edge.

The two vertical hairlines are real `border-left` / `border-right` on the container — not
pseudo-elements, not a background gradient. Section divisions are `border-top: 1px` on each band and
**no band ever has a bottom border**; the next band's top border serves. Because the sides, the
section dividers and the in-grid dividers are all the same 1px border on nested boxes of identical
width, every line on the page meets every other line exactly. There is no alignment work left to get
wrong.

**Partial borders — the detail most likely to be missed.** Grid cells do not each carry a box.
Adjacent cells share a single hairline, which is what makes the page read as one ruled sheet rather
than a tray of cards. Implement with a `:not(:last-child)` border rather than a border per cell:

```css
.split > :not(:last-child) { border-right: 1px solid var(--rule); }
.stack > :not(:last-child) { border-bottom: 1px solid var(--rule); }
```

The measured border patterns on the reference are `1/1/0/1`, `0/1/0/0`, `0/1/0/1`, `0/0/1/0` —
partial, and always radius 0. **Radius stays 0px on every grid cell**, without exception.

**Cell widths come from halving and thirding 1440, not from a 12-column token system.** The
recurring measured widths are 719/720 (halves), 647/791 (the 0.9fr/1.1fr split), 639/599 (thirds
and a narrower two-up), 479/480 (three across), 401 (quarters). Any bento must resolve to those
fractions. Do not introduce a grid framework.

## 2.2 Rhythm — fixed

**There are no vertical margins anywhere between bands.** Rhythm comes from exactly two things:
fixed band heights, and one uniform cell padding.

| Element | Height |
|---|---|
| Header | 81px |
| Tick spacer under header | 0px |
| Hero copy block | ~409px (`pt-14 pb-6`, content-driven) |
| Hero visual band | 640px |
| Centred interstitial | 352px |
| Left-aligned interstitial | 320px |
| Three-across strip | 320px |
| Product / feature row | 480px minimum, content-driven above that |
| Pure spacer band | 120px |
| Sticky tab bar | 53px |
| Legal strip | 61px |

Cell padding is **40px on desktop, 20–24px on mobile**, with essentially no exceptions. Uniform
padding across twenty-plus cells is what makes a dense page feel calm, and it means the ratio of ink
to air is identical everywhere. The two sanctioned exceptions are the footer link farm (96px) and a
deliberately inset visual (100px each side on a product row).

Internal spacing inside a copy cell: `60px` between blocks, `20px` inside the copy stack, `12px`
between checkmark items, `24px` above a button. Everything is `4 × n`, dominated by 20 and 40.

## 2.3 The ticks — fixed

The signature detail, and the highest ratio of perceived craft to effort on the whole reference.
Two 10×10 CSS triangles made of 5px borders, three sides transparent, positioned to straddle a
band's top rule at both ends of the column:

```css
.band--ticks::before, .band--ticks::after {
  content: ''; width: 0; height: 0; position: absolute; top: -5px;
  border: 5px solid transparent;
}
.band--ticks::before { left: 0;  border-left-color:  var(--rule); }
.band--ticks::after  { right: 0; border-right-color: var(--rule); }
```

**Ticks mark chapter joints, not rows.** Six to eight uses on a 6000–8500px page and no more. The
sanctioned positions: a zero-height band directly under the header (whose only job is to place two
ticks on the header's bottom rule), the hero band, the 1px rule immediately above the sticky tab
bar, the customer-claim band, the closing CTA band, the footer link band, the legal strip. **Never
on a repeating product row.** A direction may vary *how many* of the eight it uses; it may not
invent a ninth position.

## 2.4 Shells — fixed vocabulary, free mix

Fourteen shells. Only three things vary between them: padding (40 or 0), background (none, flat, or
image), and whether the inner object is inset or bleeds.

| ID | Shell | Use it when |

| S1 | Header bar, 81px, `px-6 py-5`, `border-bottom` | Once, at the top |
| S2 | Hero copy block, no top border, inner column 672px centred | Once |

| S5 | Three-across, 479px cells, `justify-between` so bottom objects align | Three peer facts of equal weight |

who has learned the pattern once should never have to re-scan. Copy cells never bleed; artefact
cells may. Two adjacent bands never use the same shell. Two adjacent artefact cells never use the
same treatment (see the visual budget in Part 4).

## 2.5 The tab bar — fixed mechanics

The single most transferable decision on the reference, and the one place the reference is
measurably broken, so copy the idea and fix the implementation.

It is a **sticky mono index bar with scroll-spy over a plain anchored stack**. All the sections it
indexes are in the DOM simultaneously. Nothing mounts, unmounts or crossfades. It gets the
affordance of tabs with none of the state, and the page stays linkable, scrollable and printable.

Fixed: `position: sticky; top: 0`, 53px tall (52 + 1px rule), **opaque** ground, `z-index: 10`,
bottom hairline. At ≥ 640px the list is `grid-template-columns: repeat(6, 1fr)` — six equal ruled
cells, hairline between all but the last, labels dead centre. Below 640px it is a `flex` row with
`overflow-x: auto` and hidden scrollbars. Labels are Geist Mono 14, `-0.35px` tracking, single
lowercase words, `white-space: nowrap`. Active is full ink/white, inactive is `#867E8E`,
`transition-colors 200ms`. The indicator is a 2px bar pinned to `bottom: 0`, absolutely positioned,
sliding and resizing with `transition: all 300ms cubic-bezier(0, 0, .2, 1)`.

Four things we do differently from the reference, all of them fixes:

1. **Drive the indicator from a `ResizeObserver` on the list**, not from a `setTimeout(…, 100)` at
   mount. The reference measured a 99px underline inside a 238px cell on cold load and never
   corrected it, and measured wrong again after a resize.
2. **No `touch-action: none` on the mobile strip.** It removes a swipe users expect in order to
   protect an auto-scroll animation. Keep `overflow-x: auto` and let people drag.
3. **Use `scroll-behavior: smooth` plus `scroll-margin-top: 53px`** on each anchored section
   instead of a hand-rolled 800ms `requestAnimationFrame` easing. Two CSS lines, honours
   `prefers-reduced-motion`, and does not fight the browser's anchor handling.
4. Scroll-spy is a scan line **200px below the viewport top**, first match wins, plus a
   force-last-tab rule within 100px of the document bottom. Passive listener, rAF-coalesced.

Main-page tabs (six lowercase words indexing the six product bands): `code` · `agents` · `context` ·
`review` · `delivery` · `pricing`. Locadex product-page tabs are in Part 4.

## 2.6 Type — fixed curve, free assignment

**Three faces, three jobs, nothing crosses.** Switzer for editorial, Inter for prose, Geist Mono
for anything labelled, measured, or code.

**The argument for the third face.** Switzer and Inter are the loaded pair and a third *display*
face would be indefensible. Geist Mono is not a third display face; it is a functional requirement
with four non-negotiable jobs — code panels, terminal transcripts, locale tags and metric labels,
and tab labels. Every one of those is content that must be monospaced to be correct, not styled to
be pretty. `apps/landing` already ships Geist Mono as `--font-mono`, so it costs nothing new. **No
direction gets a fourth face.** If a direction wants a serif for a pull-quote, the answer is no.

**The curve, measured off both reference sites, is identical on both and is fixed here.** Tracking
tightens as size grows; leading compresses toward 1.0 at display sizes; tracking is zero at 30px and
below.

| Role | Face / weight | Size → | Line-height | Tracking |
|---|---|---|---|---|
| h1 | Switzer **500** | 36 → 48 (≥640) → **60** (≥768) | 67.2 (1.12) | **−3px** (−0.05em) |
| h2 | Switzer 500 | 30 → **48** (≥768) | 48 (1.00) | −1.2px (−0.025em) |
| h3 | Switzer 500 | 24 → **40** | 53.3 | −1px (−0.025em) |
| h4 (row/cell head) | Switzer 500 | 20 → **30** | 36 (1.2) | **normal** |
| h5 | Switzer 500 | 18 → **24** | 28 | normal |
| h6 | Switzer 500 | 16 → **20** | 28 | normal |
| Body `p` / `li` | Inter 400 | 16 → **18** (≥768) | 28 | normal |
| Row subhead | Inter 400 | 16 | 24 | normal |
| Checklist item | Inter 400 | 16 | 24 | −0.4px |
| Button | Inter **500** | 16 | 22.4 | normal |
| Stat number | Inter **500** | 16 → 20 | 28 | normal |
| Metric / data label | Geist Mono 400 | **12** | 16 | **+0.3px**, uppercase |
| Tab label | Geist Mono 400 | 14 | 20 | −0.35px |
| Terminal body | Geist Mono 400 | 14 | **24** | normal |
| Inline code chip | Geist Mono 400 | 16 | 24 | normal |

**Switzer never exceeds weight 500.** Not 600, not 700, nowhere, at no size, in no direction. This
is the single decision that keeps a 60px headline calm, and it is the easiest thing on this list to
break by accident. `text-wrap: balance` on every heading; `text-pretty` on body copy. Subheads are
capped at 400–448px so they never run past two lines.

**The no-eyebrow law, and the one place the references and the founder collide.** The oxc product
row opens with a 12px mono uppercase category label *above* the heading. The founder's instruction
for this round is explicit: no eyebrows above headings; a section starts with its heading. The
founder wins. Geist Mono 12 survives in exactly four positions and no others:

1. **Tab labels** in the sticky bar.
2. **Data labels** in a fixed gutter inside a chart or table, where they are an axis.
3. **A status word appended to the end of a heading**, in parentheses, at the heading's own size and
   in the accent colour — `Formatter (Beta)` becomes `Google Slides (Beta)`. In parentheses,
   grammatically and visually parenthetical; no pill, no chip, no background, no amber.
4. **Footnotes and captions below** the thing they describe, carrying workload, machine, provenance
   or a source link in one 12px line.

What a builder must never write: a mono label on its own line above an `h2`, `h3` or `h4`. If a
label seems necessary to explain a section, the heading is not doing its job.

**Free per direction:** which face carries section headings (see Part 3 — REFLOW promotes Inter,
LEDGER promotes Geist Mono, the other three use Switzer), the display size actually used at the top
of the range, and whether an oversized *specimen* appears as an artefact (CALIPER's 160px word is an
artefact, not a heading, and is therefore exempt from the curve).

## 2.7 Colour — fixed base, free accent

```
Light                          Dark
paper      #FFFFFF             ground     #16171D
ink        #16171D             primary    #FFFFFF
rule       #E5E4E7             rule       #3B3440
muted      #867E8E             muted      #867E8E   (the same value in both)
alt surface#F4F3EC             alt/panel  #14121A
                               secondary  rgba(255,255,255,.70)
```

`#867E8E` is the workhorse. It carries all body copy, all mono labels, all inactive tabs, and it is
by far the most-used colour on the reference (92 elements). Text has only three levels — heading
ink, body muted, and in dark contexts white then white-at-70 — and the mono label shares the body
colour rather than getting a fourth tone. Do not add one.

**There is no surface fill system.** Cells are transparent and separated by rules. Anything that
needs to read as a surface is instead a *dark object on paper* (`#16171D`, radius 12) or a *dark
panel inside a visual cell* (`#14121A`, radius `4px 0 0 4px`). **No shadows anywhere in the content
area.** The only sanctioned `box-shadow` on the reference is a button hover lift, and we drop even
that — keep the outline button and the invert-on-hover, drop the `scale(1.05)` and the shadow,
because in a design built from 1px rules and 2px radii that is the one bouncy element and the one
that will date.

**Rules have exactly two idioms:** an opaque grey hairline in light, a translucent white hairline on
dark objects — `rgba(255,255,255,.30)` for a hero terminal ring, `.20` for a code panel, `.10` for
an install card or a segmented control. Never a translucent black.

**Panel rings use `outline` + `outline-offset`, never `border`.** Because outlines do not affect
layout you get a hairline halo floating 2–3px away from the panel — the "lit box" look — for free,
and it never shifts a grid.

**Radius discipline.** 0 on grid cells. 4px on code chips, inline code, code panels and small
interior objects. 6px on a segmented control. 8px on buttons and on the *top corners only* of a
terminal window. 12px on install cards. **Asymmetric radius is a bleed signal** and is never
decorative: `4px 0 0 4px` means "this continues past the right edge", `8px 8px 0 0` means "this
continues past the bottom edge". Squared corners always mean continuation.

**The accent, fixed rules and free value.** One accent per direction. It is allowed **at most two
dozen appearances on a long page**, and it is forbidden on: any heading, any body sentence, any
border, any button, any button label, any tab, and the underline indicator. On the reference the
accent hue appears once, as a bullet marker. That level of restraint is the rule, not the exception.
Every direction's accent, and the specific places it is allowed, is enumerated in Part 3.

Explicitly banned in all five: decorative gradients, gradient text, gradient borders, coloured
glows, rainbow fills, green status dots, coloured pills, and the `rainbow` button variant currently
on the site. The prismatic field from `AESTHETIC_ADDENDUM` §2b is **not** part of this system — it
belongs to the superseded maximal explorations. If a direction wants it, the only sanctioned place is
inside one dark inset panel or cropped as a thin foil band, composed per §2b so that content aligns
to the light rather than floating over it, and no direction in Part 3 asks for it.

## 2.8 Light / dark balance — fixed shape, free proportion

**The main page is light-dominant with exactly one dark pivot band plus a dark footer**, so the page
reads light → dark → light → dark. The pivot band is a `<section data-theme="dark">` that paints
`#16171D` edge to edge across the whole viewport while the nested `.band`s inside it redraw their
rules in `#3B3440` automatically. One attribute, one theme switch on the entire page, and the layout
inside the band is *identical* to the layout outside it — same class, same 40px padding, same
dividers — so the band reads as the same document seen under different light rather than as a
different design.

It also solves an editorial problem: the densest content on the page (the agent, the diff, the
review workspace) goes into one dark block instead of ten alternating light and dark cells.

**Fixed:** exactly one pivot band; the pivot band holds a centred interstitial, a ticked hairline,
the sticky tab bar and the repeating rows; the footer is dark; the theme switch is one attribute.
**Free:** the pivot band's share of page height, from 30% to 45%, and whether inset panels in the
light sections are dark objects or paper cells.

**Product pages invert this.** They run dark throughout, following oxc, but — and this is the one
place we deliberately do *not* copy the reference — the light token set is live and the theme toggle
works. oxc hardcodes `data-theme="dark"` in the markup and ships a complete unused light set;
localisation buyers include marketing, docs and product people, and GT's own dashboard is not a
terminal.

## 2.9 Product-row anatomy — fixed

Copy is written into a fixed frame, so writing a product page is filling slots rather than designing
sections. In order, top to bottom, inside the copy cell:

1. **Heading.** Switzer 500, 30/36, normal tracking. Branded tools take the form
   `<Name>: <incumbent>-compatible <category>`; unbranded libraries use their bare npm package name.
   A status word may be appended in parentheses in the accent colour at the same size.
2. **One-line subhead.** Inter 16/24, secondary colour, capped at **400px**, ≤ 60 characters, a
   benefit, no terminal period.
3. **Checkmark list.** Two to four items, `gap: 12px`, each `padding-left: 32px`, Inter 16/24 at
   `-0.4px`, **full ink/white** — brighter than the subhead above it, because these are the claims.
   The bullet is not a tick glyph; it is a 20×20 inline SVG data-URI: `circle r=9` stroked
   `#3B3440` at 0.5, plus white 1.2-width arcs on the **left and right only** (gaps at top and
   bottom — a deliberately broken ring), plus a bevel-joined check. It reads as a machined part.
4. **Inline code chips** inside those items: Geist Mono 16/24, `#3B3440` at 50% fill, `outline: 1px
   #867E8E`, radius 4, padding `2px 6px`, margin `0 4px`. Chips carry incumbent names and API names
   only — `gt-next`, `next-intl`, `i18next`, `.po`, `.xliff`, `<T>`, `gt.config.json`.
5. **One 38px outline button**, `width: fit-content`, 24px above it, and **the same label on every
   row**: `Read the docs`. Never "Learn more". A product page that indexes documentation converts
   developers better than one that funnels.

**Claim shape.** Number-first fragments, ordered speed → scale → capability → ecosystem, each ≤ one
line at 400px, each led by the number when there is one, with the compared thing in a chip. No verbs
where a number will do. Every item is a fragment; none takes terminal punctuation. GT's stock:
"`<T>` wrapping with zero config", "40+ locales from one `gt.config.json`", "2 minutes from
`npx locadex init` to first PR", "drop-in for `next-intl`", "0 strings extracted by hand".

**The visual cell.** `padding: 0` if it bleeds, 40–100px if it is inset. **Inset is the default for
GT.** The reference's `justify-end` + `padding-right: 0` bleed works only because its screenshot has
a rounded frame baked into the bitmap; with live DOM or an SVG diagram it reads as a layout bug.
Bleed at most once per page, on purpose, and only for an artefact that has its own frame.

## 2.10 Motion — fixed vocabulary

The easing vocabulary is deliberately tiny. Four values cover the entire site.

| Purpose | Spec |
|---|---|
| Entrance (a panel arriving) | `transform 1000ms cubic-bezier(0.16, 1, 0.3, 1)`, 96px rise |
| Secondary entrance | 700ms, `delay: 300ms`, same easing |
| Terminal typing | 18ms per character |
| Terminal line stagger | 180–220ms per line |
| Line reveal | `opacity/transform .22s` from `opacity: 0; translateY(.35rem)` |
| Transcript completion hold | 900–1200ms |
| Layout re-measure (FLIP) | 350–600ms, `power3.out` |
| Tab underline | `all 300ms cubic-bezier(0, 0, .2, 1)` |
| Hover | 75–200ms `cubic-bezier(.4, 0, .2, 1)` |

**Playback discipline, fixed.** `autoplay: false` on everything. An `IntersectionObserver` at
`threshold: 0.1` (0.35 for anything expensive) fires `play()` **once** and never again. Teardown on
unmount. A separate lighter asset below 768px. Nothing parallaxes, nothing scroll-scrubs, and at
most **two** ambient loops exist on a page — a blinking terminal caret counts as one.

**`prefers-reduced-motion` is honoured everywhere.** This is the one place we are strictly better
than the reference, which honours it in exactly one component and lets its hero, its headline sweep
and its 16-second button loop ignore it. Every animated module in Part 1 nominates a canonical still;
that still *is* the reduced-motion render. `dither.ts` already does this correctly — it draws one
static frame and never schedules a rAF loop.

**Free per direction:** which single module gets the page's one "expensive" entrance, and whether the
direction's signature technique animates at all. HALFTONE and LEDGER can be almost entirely static
and lose nothing.

## 2.11 What is fixed and what is free — the summary a builder can check against

**Fixed, and a direction that varies it is broken:** the 1440 column and its border mechanics; the
`border-top`-only band rule; partial cell borders and radius 0 on cells; the halving/thirding cell
widths; the band-height table; 40px cell padding; zero vertical margins; the tick geometry and the
eight sanctioned tick positions; the fourteen shells and the copy-left/artefact-right rule; the tab
bar's mechanics and its four fixes; the three faces and their three jobs; the type curve and Switzer
capped at 500; the no-eyebrow law and the four surviving mono positions; the base palette and
`#867E8E` as the workhorse; three text levels; no surface fill system; no shadows; the two rule
idioms; `outline` for rings; the radius scale and asymmetric radius as a bleed signal; the accent
budget of two dozen and the six places an accent may not go; one dark pivot band switched by one
attribute; the product-row anatomy and its repeated button label; the motion easings and playback
discipline; `prefers-reduced-motion` everywhere; the still-frame law; the artefact law.

**Free, and this is where a direction earns its name:** the signature demonstration technique; the
accent value and the specific places it appears; which face carries section headings; the dark
band's share of page height (30–45%); the shell mix and band order below the trust band; interstitial
heights (320 or 352); how many of the eight tick positions are used; whether the hero visual is a
full-bleed band or a split; whether the `#F4F3EC` second surface appears and where; the micro-radius
of interior objects; which single module gets the page's one expensive entrance.

**Fixed, and non-negotiable regardless of direction — the band order of the first four bands:**
header, tick spacer, hero copy, hero visual, trust. Every direction opens identically. Divergence
starts at band six.

# PART 3 — THE FIVE DIRECTIONS

Five directions, one frame. Each has a codename, a slug, a concept in one paragraph, a type
assignment inside the fixed triad, a colour story, one signature demonstration technique, and a
statement of the modules it wins and why. Each direction is minimalist under the same definition and
none of them uses ornament, decorative gradients, or eyebrows.

A note on how these differ from each other, because "five minimalist directions" is a phrase that
invites five versions of the same page. They differ on **what the page's images are made of**.
HALFTONE's images are dither cells. CALIPER's are measurement. REFLOW's are the DOM itself,
mid-change. LEDGER's are aligned rows of type. REDLINE's are real product output, diffed. Those are
five materially different production pipelines, which is why the five pages will not converge under
pressure — a builder physically cannot drift HALFTONE toward REDLINE, because the assets are made by
different code.

---

## 1 — HALFTONE · `halftone`

**Concept.** The page is printed, not rendered. Every image on it is one bit deep: black cells on
white paper, ordered by an 8×8 Bayer matrix, with no anti-aliasing, no grey, and no colour anywhere
on any band. The argument is that a localisation platform's imagery should be *typographic in
origin* — made of the same ink as the text — and a 1-bit halftone is the only image process that is
literally made of the same two values as type on paper. It gives the direction a second benefit that
matters for a five-way comparison: every visual on the page is produced by one function with one
grain size, so nine bento thumbnails, a globe, a logo wall and a footer wordmark all belong to each
other without any styling work.

**Type.** Switzer 500 for all headings on the fixed curve, up to the full 60px at h1 — a large quiet
headline is what a dithered field wants beside it. Inter 400 body. Geist Mono for labels, code and
tabs. Nothing is promoted or demoted; HALFTONE's identity is entirely in its imagery, and mixing that
with a type inversion would be two ideas competing.

**Colour.** None. HALFTONE is the only fully achromatic direction: paper `#FFFFFF`, ink `#16171D`,
rule `#E5E4E7`, muted `#867E8E`, and in the dark band ground `#16171D` with white ink. Its accent is
**inversion** — a black cell in a white page, or a white cell in the dark band — and it is allowed
in the same two-dozen-appearance budget as any hue. This is a real design decision and should be
argued in the presentation, not apologised for: a page whose imagery is 1-bit has already spent its
contrast budget, and adding a hue on top would flatten the dither.

**Signature technique — the 1-bit field.** Every non-type visual is `ditherToCanvas` or
`createDitherLoop` output from `src/lib/dither.ts`. The rules a builder must follow, because the
module's own header spells out the failure modes:

- **Never render at `devicePixelRatio`.** The module deliberately draws one device pixel per dither
  cell and lets CSS upscale with `image-rendering: pixelated`. Rendering at DPR makes each cell
  subpixel-sized on retina and the ordered structure collapses back into flat grey — the exact
  failure the technique exists to avoid.
- **`scale` is the design control.** `scale: 1` is invisible structure; `3–4` reads as halftone;
  `8+` reads as deliberate chunky pixel art. Use `scale: 3` for full-bleed fields, `scale: 4` for
  the nine bento thumbnails, `scale: 2` for logo marks, `scale: 6` for the footer wordmark.
- **Cost.** At `scale: 3` on a 1440×900 hero the buffer is 144k cells and everything except
  `radialBurst` animates comfortably inside a 30fps budget. `radialBurst` is 15.1ms per frame at that
  size, so animate it at `scale: 4+` or render it once and leave it static. Never animate a full-bleed
  field at `scale: 1`.
- **Field assignments.** `globe()` for M13 (`graticule: 0.3, meridians: 12, parallels: 7, spin: 0.18`
  — and note that graticule plus landmass are 70% of its cost, so drop landmass if a frame budget is
  tight). `makeGlyphField()` for the M18 footer wordmark, the M03 logo marks, and any place a letter
  needs to be an image; call it after `document.fonts.ready` or the metrics come from the fallback
  family. `streakBands()` for the B5 closing-CTA background at very low bias. `gradientRamp()` as the
  calibration field and for any bento thumbnail that needs a ground. `radialBurst()` exactly once, in
  the hero, static.
- **Composition.** Fields are just functions, so `multiplyFields`, `maxFields` and `mixFields` compose
  them — a glyph masked by a ramp, a globe unioned with bands. Prefer composition over new fields.

**Hero variant.** The 640px hero visual band is split: the code panel on the left as specified in
M02, and on the right, instead of a browser frame, a **1-bit browser frame** — real DOM chrome drawn
with hairlines, with the rendered page's *background* being a `radialBurst` field at `scale: 4`,
`coreRadius: 0.13`, `intensity: 0.6`, static, and the translated text set in real type over it. The
dark centre of the burst is where the text sits, per the composition principle: content goes to the
light, not the light behind the content. The tab strip of six native language names sits on the
burst's horizontal axis.

**Modules it wins:** M03 Trust, M13 Locales, M14 Bentos, M18 Footer. In every case the win is the
same win — HALFTONE is the only direction with a *mechanism* for producing many small consistent
images, and those four modules are precisely the ones that need many small consistent images. The
logo wall, the globe, the nine thumbnails and the footer wordmark are the four places the other four
directions will look assembled and HALFTONE will look printed.

**Its risk, stated honestly for the presentation.** A 1-bit page can read as retro if the grain is
too coarse or as accidental if it is too fine. `scale: 3` at 144k cells is the calibrated value;
resist the temptation to go chunkier for effect.

## 2 — CALIPER · `caliper`

**Concept.** The page is a measuring instrument pointed at language. Every claim is drawn as a
measurement: hairline guides with labelled metrics, bezier control points on real outlines,
sidebearing bands, advance brackets, ruler-tick margins, and tiny mono labels naming what changed.
The founder's reference — grey filled letterforms with visible control points and labelled metric
guides in mono caps — is the look, and GT's version measures the *same word across languages*, which
converts a beautiful typographic diagram into a product argument: translation is a layout problem,
and we are the people who measure it.

The discipline that makes CALIPER work rather than becoming decoration: **every number on the page is
measured at render, never typed.** Advance widths come from `measureText`, expansion deltas are
computed from those widths, control points are sampled from real outlines. A fake ruler is worse
than no ruler.

**Type.** Switzer plays two roles at two altitudes, and this is CALIPER's one type idea. As
**heading**, Switzer 500 on the fixed curve, unchanged. As **specimen**, Switzer 500 at 96–160px,
filled `#D8D6DC` rather than ink, with its outline instrumented — this is an artefact, not a heading,
and is therefore exempt from the curve. Inter 400 body. Geist Mono 11–12 for every metric label, at
`+0.3px` uppercase; CALIPER uses more mono than any other direction, but always as a label attached
to a thing, never as a line above a heading. Dogfooding note worth putting in the presentation: the
type CALIPER measures is the type CALIPER is set in.

**Colour.** One accent, borrowed from the reference's own convention: the sidebearing band. A pale
sage fill `#DCE6DA` with a `#4F6B4B` hairline, used **only** on sidebearing bands, expansion bands
and measurement brackets — roughly twenty appearances on the page, all of them inside instruments.
Never on a heading, a link, a button or a rule. Everything else is the fixed base palette.

**Signature technique — the annotated artefact.** A CALIPER diagram is always a real thing with
measurement drawn over it. The vocabulary is fixed so that twelve instruments look like one
instrument:

- **Guide:** 1px horizontal or vertical hairline at 40% opacity, full width of its cell, with a
  Geist Mono 11 uppercase label at the left margin. The baseline guide is the only one at full
  opacity.
- **Control point:** 4px filled square in ink at an on-curve point, 3px hollow circle at an off-curve
  handle, joined by a 1px hairline.
- **Sidebearing / expansion band:** sage fill, sage hairline at both edges.
- **Advance bracket:** 1px horizontal line with 4px vertical end caps, labelled with the measured
  value in Geist Mono 12 centred above it.
- **Delta bracket:** two stacked advance brackets, the shorter one ghosted, with the percentage
  difference labelled once.
- **Leader:** 1px hairline from a label to the thing it names, no arrowhead, one 90° bend maximum.
- **Ruler tick margin:** 4px marks every 8px, 8px marks every 40px, along the top and bottom of an
  instrument band.

**Hero variant.** CALIPER's hero visual band is the M07 instrument itself, at full 1440 width, as
band four — the specimen cycling `Hello → Hola → こんにちは → مرحبا → Übersetzen` with its guides
re-measuring. The code panel and browser frame of the standard M02 hero move down into band six as a
split row. This is the one direction permitted to reorder the fixed opening, and the reason is
strategic: CALIPER's whole case is made in its second impression, and burying the instrument mid-page
wastes it.

**Modules it wins:** M07 Measure (its thesis), M09 Context Groups (the brackets between the wrong
answer and the right one, labelled `GLOSSARY` and `DIRECTIVE`, are what turn a before/after into an
explanation), M16 Proof (a testimonial that carries its own expansion data), plus the stated
exception of the M12 Google Slides row, which is CALIPER's strongest single cell anywhere — a layout
claim wants a measured layout.

**Its risk.** Instruments are seductive to build and easy to over-apply; a page where the pricing
table and the footer both carry ruler ticks has stopped measuring anything. Cap it: no more than
four instruments on the page, and every instrument must be measuring something that changes across
languages.

## 3 — REFLOW · `reflow`

**Concept.** The page is a UI caught mid-translation. Its hero is not a picture of localisation — it
is real DOM that changes language while you watch, and the layout visibly re-measures around it:
buttons widen for German, cards grow taller, a nav row reflows, a badge breaks to two lines and its
row re-balances. The argument is the one the feature inventory calls the most under-shown thing GT
has: translation is not a text-swap, it is a layout event, and the only honest way to say that is to
let the reader watch a layout survive one.

The non-negotiable that defines the direction: **a text swap with no container resize is an automatic
fail.** Every language change in REFLOW measures before and after with `getBoundingClientRect` and
animates width, height and position with a FLIP transition. If the containers do not move, the
direction has not been built.

**Type.** REFLOW is the one direction that promotes **Inter to section headings** — h2 through h6 in
Inter 500 on the fixed size curve, with Switzer 500 reserved for the h1 alone. The argument is
specific rather than stylistic: REFLOW's subject is *UI text*, UI text is Inter, and a page whose
headings are the same face as the strings it is re-measuring reads as one continuous surface rather
than as editorial commentary on a product. Geist Mono for labels, tabs, code, and every delta
readout.

**Colour.** GT's own accent blue, `#458DFF` in light and `#6BA5FF` in dark, used in **one role
only**: the measurement bracket and its delta label on whichever element just changed size. A 1px
bracket with 4px end caps and a Geist Mono 12 readout — `+18%`, `−31%`, `+2 lines`. That is roughly
twenty appearances across the page and the blue appears nowhere else: not on a link, not on a button,
not on a tab, not on the underline indicator. The blue *means* "this is the thing that just changed
size," and it means nothing else.

**Signature technique — the live re-measure.** Implementation is fixed so five modules behave
identically: capture `getBoundingClientRect` for every participating element before the locale
change; apply the change; capture again; invert the deltas as transforms; play them out over 420ms
`power3.out` (range 350–600ms). Text crossfades in 220ms *inside* the moving container, so the
reader sees the box move and the words change as one event. The blue bracket draws on the element
with the largest delta, holds for 1200ms, and fades.

The other half of the technique is the **ghost**, and it is what makes REFLOW survive a still-frame
review: behind every re-measured container, REFLOW leaves a 1px blue dashed outline of the container's
*previous* size, at 30% opacity, for the duration of the hold. A single screenshot therefore contains
both the before and the after. Without the ghost, REFLOW's canonical stills would all be "a UI at
rest", which is to say nothing at all. With it, every still is a measurement.

**Hero variant.** The 640px hero visual is the M02 composition with the right half built as live DOM
rather than a rendered frame — a small real website (heading, date line, paragraph, two buttons, a
five-item nav) inside browser chrome, cycling `en → es → ja → de → zh → fr` on a 3.2s dwell. On each
change: the heading's box re-measures, the paragraph gains or loses a line and the frame grows, the
primary button widens, and one blue bracket lands on the largest change with its delta. A labelled
cursor chip reading `locadex` hops to the element it is about to change, 300ms before the change, so
the reader's eye is in the right place. The code panel on the left never moves.

**Modules it wins:** M02 Hero (mandated and earned), M05 Story (six consecutive re-measures used as
narration, with the mock site being re-laid-out at each of the six stations rather than six separate
artefact strips), M11 Delivery (two of its three cells are re-measures, and the ghost outline is the
only way to show "the text changed and the deploy did not happen" in a still).

**Its risk.** FLIP on real DOM is the most fragile thing any of the five directions asks for, and it
will look broken rather than impressive if a transition is interrupted, if a font loads late, or if
`prefers-reduced-motion` is on and the fallback was not designed. Build the reduced-motion render
first: it is the canonical still — after state, ghost outline visible, delta labelled — and it must be
a good frame on its own before any animation exists.

## 4 — LEDGER · `ledger`

**Concept.** The page is a ruled ledger and every argument is made by alignment. There are almost no
pictures: a diagram in LEDGER is a table in which one column is the invariant and the others are
locales, and the reader understands the claim by seeing what stays put. It is the most severe of the
five and the most legible in a still, and it is the direction that best fits the parts of GT that are
genuinely tabular — six SDKs against nine capabilities, six locales against four entries, seven
workflows against seven rates, a source column against five target columns.

The reason it is not merely "the boring one": alignment is an argument that a picture cannot make.
"`gt.config.json` is the same in all six" is a *column*. "The Spanish is approved and the Japanese is
not" is a *row with two different cells*. "The base rate and the context surcharge are two separate
things you are buying" is *two line items and a rule above a total*. LEDGER says those things by
laying them out, and then says nothing else.

**Type.** LEDGER promotes **Geist Mono to section headings** — h4 through h6 in Geist Mono 400 at the
fixed sizes with tracking at zero, sentence case, not uppercase — while h1 and h2 stay Switzer 500.
The argument: a ledger's voice is monospaced, and in a page where every cell that holds data is mono,
a mono cell-heading makes the table and its title one object. Body prose stays Inter 400 and there is
less of it in LEDGER than in any other direction. Numbers are Inter 500 where they are display stats
and Geist Mono where they are data — and in LEDGER they are almost always data.

**Colour.** No hue at all. LEDGER's second value is a **surface**: `#F4F3EC` beige, the frame's one
sanctioned tinted light surface, used to mark the **invariant column** in every table on the page.
The `gt.config.json` column in M06, the `Source` column in M10, the selected rate row in M17, the
base tag gutter in M13. Roughly a dozen appearances, every one of them meaning "this is the thing
that does not change." In the dark band the same role is played by `#14121A` against `#16171D` — a
two-value ground delta and a 1px rule, no shadow, exactly as the frame specifies.

**Signature technique — the aligned column.** A LEDGER diagram is a real table, built with the page's
own hairlines rather than table chrome, and it obeys five rules:

1. **A fixed label gutter.** 96px on mobile, 144px on desktop, `flex-shrink: 0`, Geist Mono 12
   uppercase at `+0.3px`. Every row starts at the same x, so labels form a column rather than a
   ragged edge. This is the reference's bar-chart geometry, and it generalises to every table.
2. **One column is the invariant**, tinted `#F4F3EC`, and it is always the leftmost or the rightmost —
   never in the middle, where it would read as an anomaly rather than a constant.
3. **Numbers right-align on a shared decimal.** Values are prefixed with a slash where they are
   measurements — `/ 26.3ms`, `/ 47 files` — following the reference's convention.
4. **State lives in the margin**, as a hairline chip in the row's rightmost 96px, never as a fill on
   the cell.
5. **Bars, where they appear**, use the reference's measured geometry wholesale: 24px track, 2px
   radius, `#14121A` ground, fill width set inline as a percentage, `transition-transform 660ms
   cubic-bezier(0.65, 0, 0.35, 1)`, rows separated by 24px, and the winner marked by exactly three
   signals and no fourth — emphasised fill, white label, white value. **Watch the polarity:** the
   reference's chart is "shortest bar wins" because its quantity is time. GT's quantities are mostly
   "more is better" (locales shipped, strings covered, PRs merged), so either the longest bar wins or
   the axis has to be re-labelled. A reader who has seen one convention will misread the other in a
   glance, so every bar chart carries a 12px footnote naming the quantity, the workload and the
   source.

**Hero variant.** LEDGER's hero visual is not a browser frame. It is one table, 640px tall, full
column width: a `Source` column tinted beige holding four real English strings from the site's own
copy, and five locale columns — `es` `fr` `ja` `de` `zh` — holding the real translated strings from
`examples/next-ssg/public/_gt/`. Row heights are uneven because the strings are uneven, and that
unevenness is the diagram: the Japanese column is visibly narrower, the German visibly taller. A
Geist Mono 12 footnote reads `Rendered from public/_gt/[locale].json. Four entries, five locales.`
Nothing animates. It is the strongest still-frame hero of the five and the weakest loop, and that is
a legitimate trade for a presentation reviewed as stills.

**Modules it wins:** M01 Header (six ruled cells instead of a flex row — the first table on a page of
tables), M06 Frameworks (nine capabilities × six SDKs plus a beige seventh column that is filled in
every row — the invariant made literal), M10 Dashboard (a translation editor *is* a ledger, and
LEDGER can draw it with no app chrome at all, which is the only version that stops looking like a
screenshot), M17 Pricing (the rate table and the calculator become one object instead of two).

**Its risk.** Severity is one bad decision away from austerity. LEDGER needs its whitespace budget
spent generously — 40px padding is a floor, not a target, and the 120px spacer band and the 352px
interstitials are what stop eight tables in a row from reading as a spreadsheet export.

## 5 — REDLINE · `redline`

**Concept.** The page shows the product's actual output, unretouched, and the unit of proof is the
diff. Terminal transcripts, unified diffs, GitHub pull requests, generated JSON — line for line,
before and after. Nothing is illustrated. The reference's single strongest element is a *screenshot of
a terminal* reading "Finished in 45ms on 680 files with 88 rules using 10 threads", and REDLINE takes
that lesson to its conclusion: screenshot the product, do not draw it.

GT's equivalents are real and available today, which is why this direction is cheap to build and hard
to argue with: a `locadex` run log with a PR URL, a real `git diff` showing `<T>` wrapping appear, a
real GitHub PR page, the generated `_gt/ja.json` with its hashed keys and its preserved JSX tree, a
`--dry-run` ending in `0 tokens billed`, a `pnpm install` session ending in `Done in 2.4s`.

**Type.** Switzer 500 headings on the fixed curve, Inter 400 body, Geist Mono for everything inside a
panel — with one specified deviation: **inside code and diff surfaces, Geist Mono runs 13/20 rather
than 14/24.** A diff needs more lines visible per panel than a transcript does, and 13/20 fits 24
lines in a 480px cell against 20 at 14/24. Outside panels, mono stays at the fixed sizes.

**Colour.** Two accent hues, and they appear in **diff gutters and nowhere else on the page** —
that single concentration *is* REDLINE's accent budget, spent in one place instead of spread thin.
Light mode: deletion `#A32B4F`, addition `#1A6B44`. Dark mode: deletion `#F2789F`, addition
`#5BD69B`. They colour the `-`/`+` sign, the line's left gutter mark, and nothing else — not the line
text, which stays at the surface's normal ink so the code remains readable. Terminal `✓` glyphs use
the addition hue; a terminal warning line uses the deletion hue. No other element on any band in
REDLINE carries a hue.

**Signature technique — the real artefact, diffed.** Every REDLINE visual is one of five artefact
types, and no two adjacent bands use the same one:

1. **Unified diff.** `@@` hunk header, box-drawing gutter, line numbers, `-`/`+` gutter marks in the
   two hues. Real files, real paths — `app/page.tsx`, `messages/en.json`, `docs/guide.mdx`.
2. **Terminal transcript.** `#111111` fill, `28px 32px` padding, radius `8px 8px 0 0` (squared at the
   bottom because it continues past the cell edge), a hairline ring at `outline: 1px
   rgba(255,255,255,.30); outline-offset: 3px` so the window looks lit rather than bordered. Prompt
   types at 18ms/char with a blinking block caret; output lines stagger at 180–220ms; the last line is
   always the money line and it is always a real number.
3. **PR / platform surface.** GitHub PR frame, branch chip, checks panel, files-changed counter.
4. **Generated output.** The real `_gt/ja.json`, with its hashed keys and its JSX-tree structure,
   beside the source JSX, with **one hairline leader** connecting the `<h1>` in the source to
   `"t": "h1"` in the JSON. That single leader line explains the whole architecture — structure is
   preserved, only leaves are translated — with no prose at all, and it is the most under-used asset
   GT has.
5. **Masked panel.** The frame's dissolve treatment for a panel that should read as a window onto
   something larger: `mask-image: linear-gradient(to bottom, black 50%, transparent),
   linear-gradient(to right, black 50%, transparent); mask-composite: intersect` — the panel
   dissolves toward its bottom-right rather than ending. Use once per page, no more.

**Hero variant.** REDLINE's 640px hero visual is a full-bleed dark band — the one place the direction
opens its dark region early — containing a single 992px terminal window, `self-stretch` from 112px
below the band top so its bottom is clipped by the band edge. The transcript is real and it cycles
five states on the reference's own timings (900–1200ms completion, 1500ms autoplay gap, and any user
click permanently kills autoplay):

```
$ npx gt@latest
✓ Detected Next.js 15 (app router)
✓ Wrote gt.config.json
✓ Wrote .env.local
? Target locales › es fr ja de zh
$ npx gt translate
✓ 4 entries changed since last run
✓ 5 locales · 20 translations · 0 re-translated
→ public/_gt/{es,fr,ja,de,zh}.json
Finished in 3.4s. 0 local edits overwritten.
```

Every line of that is a real thing the CLI does; the last line is the money line and it answers the
question the reader was actually going to ask.

**Structural variation.** REDLINE takes the dark band's proportion to the top of the permitted range
— **45% of page height** rather than 33% — because its artefacts are dark surfaces and a page that
keeps cutting between paper and terminal is worse than one that commits. Its light sections read as
the margins around a diff.

**Modules it wins:** M04 Code (the adoption of `<T>` shown as a patch rather than as a rewrite),
M08 Locadex (a full-width real PR: this is the highest-scoring capability in the inventory and
REDLINE is built to carry it), M12 Integrations (the GitHub half rendered as the real surface),
M15 Banners (the dark pivot opening, whose 6%-opacity wall of diff markers is the one moment on any
of the five pages where a banner earns a background).

**Its risk.** A page of dark panels full of small mono type is the easiest of the five to make
illegible, and screenshots of real product output age badly the moment the product's UI changes.
Build the artefacts as live DOM wherever possible rather than as bitmaps — the frame's own hairlines
and `#14121A` panels will render a diff or a PR frame perfectly well — so that the page can be
corrected without a design round.

# PART 5 — WHAT IS STILL OPEN

Three things in this plan are not resolved by research and will be decided by building.

**One — the translated strings.** The artefact law says no builder hand-writes a translation, and the
verified corpus in `examples/next-ssg/public/_gt/{es,ja,de,fr,zh}.json` is small: it covers the
Next.js starter's strings, not GT's own marketing copy. M02, M10, M16 and LEDGER's hero all want GT's
own strings rendered in five locales. The resolution is to run the product on `apps/landing`'s own
copy and commit the output as a fixture the five builders share, before any of them starts on those
modules. Until that fixture exists, those cells render the starter strings that are already verified,
or an honest empty `Needs review` state.

**Two — the specimen outlines in CALIPER.** The instrument needs real bezier control points sampled
from Switzer's real glyph outlines, for Latin, Japanese, Arabic and a diacritic. Switzer does not
cover Japanese or Arabic, so the specimen for `こんにちは` and `مرحبا` falls back to a system face,
and a diagram that measures a different font for two of its five states is measuring the wrong thing.
Either the instrument states its fallback in a footnote — which is honest and slightly deflating — or
the CJK and Arabic states show *metric* guides only, with the control points suppressed, and the
change of representation itself becomes part of the point.

**Three — a rate table's shelf life.** M17 and §4.8 carry published rates, credit conversions and
plan contents as literal text. Rates change. Every one of those values should be rendered from
`packages/settings/src/credits.ts` and the shared services module rather than typed into a component,
and the plan list must resolve to exactly two plans with no legacy IDs able to leak. A hardcoded
`$5 / LCU` in a marketing component is the most likely thing on any of these five pages to become
untrue without anyone noticing.
